# PDF 原页阅读

PDF 阅读通过原文件和 PDF.js 呈现原始版式，TXT、Markdown、EPUB 继续使用文字分页。本文记录实现边界、历史兼容和验证入口；功能是否通过验收以具体运行结果为准。

## 原页与资源

- `GET /api/reading/books/:id/pdf/source` 根据服务端书籍版本找到原文件，支持 HEAD、单范围 206 和越界 416，不接受客户端文件路径。原文件缺失返回明确错误，保留记录。
- `GET /api/reading/books/:id/pdf/pages/:number` 从原始页章节读取所需正文块，仅返回该章节。不会因为正文块同时包含多页而混入邻页；跨块长页读取完整段落。
- Web 和服务端共用锁定的 `pdfjs-dist` 版本。Worker 随 Vite 构建发布，CMap、标准字体和 WASM 通过同源限定资源目录读取；不请求书中的远程链接，不执行脚本或 XFA。
- 只挂载一个原页的画布、文字层和标记层。关闭或切书销毁文档任务；切页、缩放取消旧渲染并释放页资源。64 KiB 范围读取，关闭自动整本预取及流下载。画布最多 1600 万像素；超过像素预算时降低采样率，CSS 页面尺寸仍按用户缩放显示。
- 页码由原始页树与导入索引核对。PDF 跳过旧全书文字分页测量。适合宽度为 100%，缩放范围 50%–300%，高缩放可在页内横向、纵向滚动。页码、缩放和相对滚动位置按原有书籍版本保存在本机；目录或记录定位可返回之前的阅读页与滚动处。

## 文字来源与历史兼容

沿用 `bookId/version/chapterId/paragraphId/offset`，不批量重写历史记录、引用或版本。每个 `cN` 对应第 N 个原始页；浏览器文字层的字符串、换行依照原导入规则处理，先按原始空行切段，再清理控制字符、trim，并按 16384 UTF-16 字符拆段且不拆代理对。

`reading-pdf-map.ts` 逐段、逐字与保存的不可变正文核对，建立文字层原始偏移到历史段落偏移的双向映射。选区范围由该映射生成，复制输出与服务端核对使用同一正文快照。划线、引用笔记及定位范围保存稳定位置，显示矩形从当前文字层 DOM Range 重新计算；不持久化缩放后的屏幕像素。无引用笔记保存位置并提供页内入口。

原文件缺失、页数不一致或文字层与历史正文不一致时，明确说明原因。历史记录与摘录不删除、不猜测迁移；可以打开对应原页时仍返回该页。无法精确映射的页禁用新的文字引用、划线及书伴读页，保留浏览器原生复制和已有记录查看。跨页旧引用在可映射的各页分别呈现交集。

新导入的无文字页以内部 U+FFFC 占位位置保存页书签与位置笔记。该字符不显示为正文、不生成文字层，也不交给书伴。已导入旧书的无文字页原本没有段落；保留原结构，可通过原页页码浏览，不为它补写新的文字身份。因此旧空页的新页书签与位置笔记入口禁用。旧无文字页不存在可迁移的有效文字记录。

## 书伴当前页

当前页与用户选区分别固定。当前页只有在该页渲染及精确来源映射成功后可用；切页、重绘和加载失败时清空当前页来源。服务端核对 PDF 当前页属于一个完整的原始页章节，端点必须为该页首段开头和末段结尾，拒绝跨页或局部内容冒充完整页。

相邻页只保存原始页范围，并由既有只读工具按本轮快照读取，不混入自动当前页。没有文字的页不给出伪造摘录。单页超过既有 16000 字符书伴预算时明确提示并禁用本页发送，不截取一部分冒充整页。文字引用依然沿用 65536 字符及外部交接长度限制。

扫描 PDF 可以阅读原页，新导入页可添加页书签和位置笔记；选区、文字划线、文字引用及书伴读页需要文字层。本次不提供 OCR、图像区域自由划线或把原页图像发送给书伴。

## 验证入口

在已安装依赖及 Playwright 浏览器的环境运行：

```bash
npm run check
npm run build
node scripts/verify-pdf-pure.mjs
npx tsx --test apps/server/tests/reading-pdf-pages.test.ts apps/server/tests/reading-pdf-outline.test.ts apps/server/tests/reading-binary-books.test.ts apps/server/tests/reading-stream-import.test.ts apps/server/tests/reading-page-tools.test.ts apps/web/tests/reading-pdf-map.test.ts apps/web/tests/reading-pdf-scene.test.ts apps/web/tests/reading-panel-layout.test.ts
npx playwright test -c playwright.pdf.config.ts
```

`verify-pdf-pure.mjs` 直接导入实际映射和字节范围实现，覆盖历史规范化、控制字符切段顺序、跨段范围、长段 Unicode、失配拒绝、范围边界及锁文件一致性。直接运行会产生 `pdf-pure-verification.json`，只有实际运行成功后才可作为通过证据。

服务端测试覆盖完整原页读取、跨正文块且不混入邻页、历史标注不变、书伴拒绝跨页和局部范围、扫描限制、HEAD/206/416、原文件缺失。端到端用含内嵌 RGB 图片、向量柱图、表格和上标公式的真实 PDF 检查非文字像素及文字层，覆盖复制、划线、笔记、书签、缩放矩形、刷新、切页后的书伴来源、加载重试、21 MiB PDF 和 390px 窄屏。专用配置覆盖 Chromium、Firefox 和 WebKit，并包含既有 TXT/Markdown/EPUB 和记录界面回归。

人工验收还需使用实际中文嵌入字体、旋转页、复杂公式、多栏、扫描图像、JPX/JBIG2、超长页及老书数据；对照原文件检查图像、字体和版式。分别模拟 Worker、原文件、正文接口、CMap、标准字体、WASM 失败，核对重试、禁用状态及 PDF.js 字体回退是否给出足够反馈；依赖资源失败可能导致 PDF.js 使用回退，不能仅凭画布出现判定成功。应观察多次快速翻页、缩放和断连后的内存、网络和来源一致性。

上述入口和测试用例不等于通过证明。验收应保留实际命令结果、三种浏览器的轨迹与截图，以及历史数据定位核对记录。
