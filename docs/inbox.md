# Inbox 契约与验收矩阵

Inbox 是既有人工请求、工具授权及外部操作的统一投影，不是第二套任务系统。顶栏数字表示服务端完整待处理总数；详情实际可见时才消除未查看点，查看不减少待处理数。业务决定通过原服务完成，响应丢失先读取原请求对账；每窗口复用一条全局 SSE。

## 身份与事实

统一 ID：人工请求使用原 requestId；目录授权使用 `authorization:<原授权 ID>`，任务中的授权镜像与普通会话授权只计一次。来源保留 taskId、sessionId、固定 artifactVersionId；没有任务的会话不虚构任务。
排序：阻塞工作优先、创建时间升序、ID 升序。服务端过滤后分页，计数读取完整集合，不以历史上限或当前页代替总数。

pending 表示当前可决定；answered 保存决定回执；invalidated/expired 表示原决定入口失效。过期授权不再计待处理，需回原会话重新发起真实工具调用，旧请求不可复活。unknown 表示外部操作已获准但结果尚待只读核对，不能再执行。

## 五类处理边界

| 类别 | 事实及动作 | 必须验证 |
| --- | --- | --- |
| 澄清 | 原 HumanRequest；回答、不采用、保持停止；范围说明仅影响任务反馈，不授予目录权限 | 空答复拒绝；暂停不自动解除；取消后迟到答复拒绝 |
| 目录授权 | 原 ToolAuthorization；单次、会话、项目、拒绝；可记住范围由服务端计算 | 普通/任务/全局会话完整汇总；过期与重启失效；Agent 无批准入口 |
| 外发 | 本轮适配 Git 分支发布：固定仓库、远端、commit 和目标 ref；用户界面批准一次 | 预览固定提交；只创建原先不存在的远端分支；只读 ls-remote 核对，未知不重推；拒绝不执行；不因此完成任务 |
| 验收 | 原 HumanRequest + 固定成果版本，接受/修改 | 新版替换旧请求；验收不授予发布；其他 pending 阻止完成 |
| 恢复 | 原 HumanRequest + 原 Run，继续/停止/安全重做 | 停止证明与工具副作用标记完整；新 Run 不重放旧命令；用户暂停和预算/依赖不被绕过 |

安全重做定义为：旧执行停止且没有未核对工具调用后，保留原工作目录变更，从新会话启动新的 Run，先核对现有文件；不回滚目录、不重放外部操作；恢复请求后的自动恢复沿用原预算。用户主动点击任务的“继续任务”会按当前偏好补充任务树额度，历史消耗与目录变更保留。无法证明停止时禁用继续和重做。

## 入口与交互

顶栏抽屉、管理完整页、任务卡、就地会话卡与 Multivac 查询使用同一身份。处理当下保留当前回执，仅用户点击下一项才切换；新请求不抢焦点。从抽屉展开到管理页属于同一次处理，保留原位回执。关闭后重新打开抽屉、或从管理导航重新进入 Inbox 时，清除已处理、失效或过期项的选中状态，显示剩余待处理事项或全部处理完毕；仍待处理和结果待核对的现场保留。历史事实保留，显式请求链接仍可查看对应回执。管理页保留桌面边界，窄屏使用抽屉。远程入口（手机）使用全屏抽屉，来源只显示服务端解析的名称，不提供跳转；目录授权只能单次，记住范围需回本机处理。来源只跳转真实会话或固定版本；失效来源明确报错。

查看与草稿独立于业务 revision，在 SQLite 持久化，所有本地窗口共享；草稿使用 revision 冲突控制，后台读取不能覆盖尚未保存的本地编辑。刷新恢复草稿；保存失败保留输入并提供重试。选择和滚动只属于本窗口，不广播。授权范围默认单次，不将旧选项自动用于新请求。

决定绑定命令 ID、请求 ID、revision 与输入。重复点击共用在途操作；失败保留输入，响应丢失先对账，重试沿用原命令；同 ID 不同参数冲突。查看写入仅发生于实际可见详情，预选、隐藏管理页不触发。

收到成功回执后，当前条目立即显示服务端决定，结束提交状态并保留原位导航。人工请求事件同样直接更新当前条目。全量历史分页在后台核对，失败或迟到旧快照不能撤回已确认回执。事件、决定后刷新、重连和远程轮询共用一条 Inbox 分页链；读取期间的新变化合并为下一轮补读。完整分页成功后应用服务端计数，失败保留已有事实和本窗口未保存草稿。

人工回应的 `answered` 只表示决定已持久化，不表示任务已开始。需要自动继续时，决定与 `Task.humanResumeIntent` 在同一短事务保存；决定接口不等待模型准入。后台按任务合并在途准入，核对最新任务边界、原 Run、已保存决定、其他请求及外发操作、停止证明、工具标记、依赖、共享预算和智能体。慢准入结束后再次核对任务与智能体版本，只有门禁均满足才原子创建新 Run、清除意图并保存继续命令回执。人工继续不补充预算；失败保留回答与可查询的等待原因。用户暂停、取消、执行边界变化或原运行替换使旧意图失效。

服务重启后，调度器完整分页扫描尚未消费的继续意图并重新核对。已经消费的意图不重放；已入队但从未开始的安全 Run 沿用现有接管规则；已开始或结果未知的执行仍进入原恢复核对流程。保存回答不能替代旧执行停止证明。

## 验收

服务端：跨来源去重、超 100 条计数、分页稳定、并发决定、重启/取消/过期、旧版本与外部结果未知。
共享状态：旧事件不复活终态、断线重读、多窗口草稿冲突、刷新恢复、处理失败保留输入；百条历史后续分页挂起不阻塞当前回执和下一项；刷新期间多次事件或远程轮询不并行读取，失败可重试且补读变化。
人工继续：可控模型准入延迟下先返回已保存回答；并发多请求全部处理后最多一次恢复；等待期间暂停/取消、预算/依赖变化、旧执行或智能体版本变化不被迟到准入绕过；回答与意图、Run 与意图消费均验证事务回滚；SQLite 重开可恢复未消费意图，未知执行不重放。
界面：五类请求、空/加载/失败态、长内容、原位回执、主动下一项、Esc/焦点循环/归还、窄屏、抽屉转管理及来源返回。

## 当前实现与验证边界

- 查询：`GET /api/inbox` 默认待处理，`status=all` 含历史；`GET /api/inbox/:id` 返回原事实与用户状态。SQLite migration 26 保存查看、草稿、外发意图与命令身份。
- 用户状态：`POST /api/inbox/:id/state` 按独立 revision 保存；多窗口冲突保留本窗口输入，只有用户主动“保留本窗口草稿并重试保存”才重新基于最新版本保存。未完成保存的输入在本标签页会话存储中备份。
- 决定：`POST /api/inbox/:id/decision` 委托原业务服务。目录授权按原请求互斥；人工请求沿用任务命令账本。外部发布在发送前落盘唯一执行权，重启只读对账。
- Multivac：`list_inbox`、`get_inbox_request`、`respond_inbox_request`；仅全局助手可转交明确的用户决定。`propose_git_publish` 可在工作会话申请固定 HEAD 发布，无任何批准执行器暴露给模型。
- 远程：白名单开放 `GET /api/inbox`、`GET /api/inbox/:id`、`GET /api/inbox/:id/artifact` 及 `POST /api/inbox/:id/state|decision|reconcile`；人工请求决定在远程同样经 Inbox 决定入口委托原服务。`session`/`project` 授权决定由服务端拒绝。远程事件流不含 Inbox 变更，页面可见时定时对账。
- 成果：Inbox 详情经 `GET /api/inbox/:id/artifact` 读取请求绑定的固定版本，不接受任意 versionId。
- 来源：`multivac://inbox/<id>` 按真实对象核对；不可用或已归档来源不显示可用会话入口。成果在原请求内读取准确 versionId，普通会话授权没有虚构 taskId。
- 生产 Git 适配只支持 HTTPS 新分支，采用本机 Git 凭据；应用不读取或验证实际登录账号，不承诺任何 Git 托管平台 API 能力。真实 push 与 ls-remote 闭环由临时本地裸仓库集成测试验证，测试专用 local transport 不在生产入口开放。
- 原生后台任务工具隔离仍仅在 macOS 验证；普通 bash 不是沙箱。恢复操作只在停止与工具标记已核对后可用，不能替代外部副作用核对。
