# 读书应用

读书位于管理 · 应用。手机首页顶栏也可直接打开。书架初始为空，内容来自用户导入的真实文件；不会注册原型示例书或模拟回复。

## 来源与位置

支持 UTF-8 TXT、Markdown、PDF 和 EPUB。TXT / Markdown 沿用 1 MiB 文本导入；PDF / EPUB 使用原文件流上传，不再经过 Base64，也不设置原来的 20 MiB 文件、8 MiB 提取正文上限。上传持续检查可用磁盘并预留 64 MiB；每次只处理一本，支持取消。每本最多 100000 段、10000 章节，单段最多 16384 个 UTF-16 字符，书架最多 200 本。

PDF 根据文件索引按需读取字节范围，逐原始页提取文字，每页作为一个章节；最多 10000 页，单页文字最多 4 Mi 个 UTF-16 字符。扫描页需要先 OCR，本版本不提供 OCR；无文字层的文件明确拒绝。PDF 密码保护需先解除。

EPUB 只读取 ZIP 目录和 OPF spine 所指向的正文资源，按阅读顺序逐章提取 XHTML；不解压未使用的图片、字体或音视频。资源目录最多 20000 项，单个被读取资源解压最多 16 MiB；不再限制整包声明的解压总量。正文加密时拒绝导入，只用于字体混淆的加密声明不影响文字提取。

解析在独立线程中进行，V8 堆预算 256 MiB，解析时间预算 2 分钟；这不是总进程 RSS 的硬上限。上传最多持续 30 分钟，HTTP 服务自身超时也适用。取消、断连、解析失败均停止线程并清理临时文件；只有完整解析并提交事务后才发布书籍与回执。超出处理预算时明确报错，不能发布半本书。

所有格式统一为可重排的文字阅读，不保留原始页面版式、图片、音视频和交互脚本；不执行 HTML 或加载书内外链。PDF / EPUB 导入后的书签、笔记、引用及书伴沿用同一套稳定原文锚点。

版本签名使用 SHA-256：文本按格式和规范化源文本计算，PDF / EPUB 按格式和原文件字节计算。版本不可变，同格式同正文重复导入返回原书，更换正文建立新书身份。原始来源保存在服务端受控目录，SQLite 保存正文快照及业务事实，不扩大项目工具目录或自动纳入知识库。

位置由书籍版本、章节、段落与 UTF-16 偏移组成，端点不能拆开代理对。浏览器原生多栏处理换行和断页，DOM Range 读取栏边界后派生页码。字号、字体加载和窗口大小变化保留原文锚点；页码不作为引用身份。

## 分块存储与按需阅读

索引只保存章节标题、段落长度、累计位置和正文块号；正文以每块最多 65536 个 UTF-16 字符或 128 段存入 SQLite，边界不拆段，也不改写既有段落 ID。旧书首次读取时在事务中迁移，原版本、书签、笔记和引用保持不变。

阅读器先取目录索引，再取当前位置的一块正文。跨块前后翻页、目录跳转、书签和笔记定位按需加载，当前正文替换后不累计保留整本 DOM；失败保留原阅读位置并允许重试。多块书的页脚明确显示“本段第 … 页”，页码跳转针对当前段，章节可从目录直接定位；小书仍保持原来的整本页码。

书架列表不读取正文；书伴核对引用时只读取涉及的块，已读上下文从边界向前读取足够的尾部，不先拼接整本。兼容的整本读取与旧 JSON 导入接口仍保留，当前 PDF / EPUB 导入与阅读界面使用流式上传及索引／正文块接口。

## 记录与草稿

书签保存原文范围并可编辑备注；划线支持跨段选区和重叠高亮。每本书最多 2000 条标注。引用同时保留正文版本和摘录，失效时保留快照并禁用定位。

阅读笔记的位置、可选引用和正文分别保存。位置记录书籍版本、章节、段落和 UTF-16 偏移，不保存排版页码；字号与窗口变化后仍可返回同一处。直接新建只记录当前位置，不自动附上整页摘录；选区写笔记记录选区起点并附上原文范围与摘录快照。编辑卡片可主动引用当前页或移除引用；移除只去掉摘录，保留位置、正文与来源讨论。旧笔记和草稿从原引用起点补齐位置，保留原摘录与版本。

阅读笔记与草稿分开持久化。每本最多 200 条笔记，单条正文最多 12000 字符。切换编辑目标时先保存、放弃或继续原草稿；关闭、翻页、切书和隐藏不会放弃草稿。未落盘输入保留本机备份，版本冲突和失败显示明确反馈，不静默覆盖其他窗口的新状态。

阅读笔记面板按原文位置展示笔记，在「笔记／划线」中切换记录。列表优先展示笔记正文，只有实际超过三行时提供“展开笔记／收起笔记”；有引用时才展示较轻样式的两行摘录，“定位原文”定位并高亮引用范围；无引用时显示“阅读时记下”，返回记录的位置，不高亮整页。操作栏左侧放展开／收起，右侧放定位原文和编辑；短笔记隐藏展开按钮但保留左侧空位，右侧操作位置保持一致。列表只保留这些操作，交给 Multivac 和删除移入编辑卡片；删除需明确确认，原子删除已保存笔记及其同名草稿，与放弃未保存修改分开。加载中不展示空状态，读取失败可就地重试。正文中有引用的笔记范围以点线标记，跨段引用的各段都可打开关联笔记；无引用笔记只在记录的段落显示笔记入口；定位显示原文范围，可返回之前的阅读处。章节栏的写笔记按钮优先恢复草稿，面板的新建按钮明确创建另一条笔记。

业务更新核对 revision，SQLite 短事务同时保存事实与幂等回执；未知结果沿用原命令对账。每个窗口继续使用既有的一条全局事件流同步变化。

## 书伴与讨论

每本书关联真实持久会话，复用现有 Pi 模型、发送、停止、历史、草稿和错误恢复链路。宿主由服务端关系确定，书伴工具集合为空，工具边界也拒绝文件与命令操作，不能作为工作会话归入项目或浏览文件。

新问题固定发送时的当前页或选区。浏览、跳页与定位不调用模型、不推进已读范围；已读到当前页末及重置都需用户明确操作。直接提供的正文只含当前引用与允许的已读材料，超限已读材料截取最后 16000 个 Unicode 字符并标明截断。模型已有知识和历史回答可能包含后文，范围裁剪与提示不能保证绝对防剧透。

Pi 请求只保留最新正文范围快照，旧范围不重复进入下一轮；历史问答及压缩后的历史摘要仍属于会话背景，重置范围不能保证模型忘记此前见过的内容。

继续追问保留原消息和原文。单独讨论创建独立会话并保存父关系，各层草稿、消息、引用和滚动独立恢复，返回不自动写回上层。每本书最多 100 个讨论，最多 16 层。各层讨论从书伴内的讨论记录、讨论路径和阅读笔记来源恢复。

## 功能范围与交接

本功能仅增加管理 · 应用 · 读书入口。书伴讨论与阅读笔记属于每本书内部，不新增独立的会话管理页、笔记应用或收集箱，也不提供“收进笔记”入口。

交给 Multivac 使用现有引用草稿和 Pi custom message，保留原阅读现场与 Multivac 草稿，只有用户发送才调用模型。交接文本与原文来源分别沿用 4 KiB UTF-8 引用限制；服务端重新核对真实来源，不发送整书或授予外发、项目资料权限。

书籍对象链接为 `multivac://book/<bookId>`。`list_books` 和 `get_book` 只查询元数据，`open_book` 按明确意图导航；窗口上下文只报告真实阅读位置。原文、记录与讨论失效时反馈原因，不猜测新来源。

## 布局

宽桌面可以同时显示左导航、正文和右书伴/笔记；较窄桌面只显示最后操作的辅助侧，仍保存另一侧偏好。手机在正文和辅助视图之间切换，回到宽屏恢复偏好。隐藏面板保留控制器，浮层独立定位，不参与正文排版，Esc 先关闭当前浮层并恢复焦点。

阅读页面直接接在应用顶栏下，使用单层工具栏、最大 680px 的居中正文及固定页脚。首次打开书籍默认收起辅助面板；页脚「本页已读」与书伴范围面板共用已读事实，回执丢失时可在正文重试原命令，避免重复写入。
