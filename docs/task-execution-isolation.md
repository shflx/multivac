# 任务执行的隔离与停止验证缺口

任务数据与原生受限执行接口已经可独立使用。本文保留最初探针的失败证据，并说明目前采用的能力边界；不引入容器运行依赖。

## 必须保持的边界

`docs/proj.md` 要求：工具文件访问、网络和子进程必须由经过验证的机制约束；无法确认旧执行停止时，不能释放冲突资源或启动冲突执行。用户授权不能绕过隔离失败。

当前 `pi-session-factory.ts` 注入本机 `read / bash / edit / write`。`pi-tool-boundary.ts` 对文件工具核对目录，对 bash 仅设置 cwd，并明确承认目录外影响未被拦截。这适用于现有工作会话，不能直接作为满足上述门禁的后台任务执行器。

## 实际探针

macOS Seatbelt 的受限 Node 子进程验证了目录外文件读写、符号链接访问与本地 TCP 连接可被拒绝；显式环境白名单可以避免继承服务端模型密钥。但这些结果不能证明整个任务已经停止。

依赖进程组的候选停止策略失败：子进程通过 `detached: true` 脱离进程组，启动器退出，向启动器进程组发送 SIGKILL 后，子进程仍在原任务目录写入。仅等待 shell 返回、Pi abort 返回或进程组消失不足以释放任务目录租约。

复现：

```sh
node scripts/probe-task-stop.mjs
```

在当前 macOS 主机得到：

```json
{"parentExited":true,"processGroupStopped":true,"detachedChildWroteAfterStop":true,"safeToReleaseLease":false}
```

退出码 1 表示停止安全门禁未通过。该探针只执行受控代码，创建并清理自己的临时目录，按返回的精确 PID 清理子进程；不调用模型、不使用用户项目、不验证 Windows。文件读取规则刻意简化以复现生命周期问题，不能用作生产沙箱配置。

真实 Pi 最小 smoke 另行运行，因未设置 `MULTIVAC_PROVIDER` 在准入校验处失败；`MULTIVAC_MODEL` 同样未配置。此结果不是模型执行失败，也不是真实任务执行证据。不得从普通测试中的 fake adapter 通过推断真实模型通过。

## 继续实现需要明确的运行前提

- 保留原生任务执行：需要跨平台可验证的进程生命周期隔离、文件/网络约束、凭据隔离与停止核对后端；不能把 worktree 或 cwd 当作替代。
- 采用容器或虚拟化任务执行：可以用隔离实例的终止与状态核对约束整个子进程树，但会新增产品部署前提，也会改变工具环境、构建工具链和项目目录挂载规则。当前开发主机存在可用的本地 Docker/OrbStack，尚未将其作为产品依赖或注入任务执行器。

## 已采用的原生受限路径

`native-task-tools.ts` 对任务工具禁止 `process-fork`，每次只运行一个可跟踪的受限进程。文件工具也在该进程中执行，环境采用白名单；网络与目录外访问默认拒绝。停止信号作用于确切的 ChildProcess，必须等待 close，不能把发送 SIGKILL 等同于已经退出。派生子进程被拒绝，因此上述脱离进程组的反例不能在这个能力集合中执行。

实际探针覆盖目录内写入、越界读写、符号链接、TCP 连接、环境变量白名单、脱离进程组的子进程创建失败，以及中止后真实退出。Pi 的工具注册替换为这些受限实现；普通工作会话保持原有行为。

此模式支持独立文件工作与无需创建子进程的命令；需要派生进程的构建、管道和网络命令会明确失败，不能宣称兼容任意本机 shell。macOS 之外未验证的隔离能力默认拒绝任务启动。暂停/取消的应用用例保留执行意图，无法取得停止事实时保留租约、进入恢复待确认；不会按标签直接释放资源。真实模型条件仍须单独验证，不以 fake adapter 测试替代。

## 任务本地 Git 的受控通道

任务 worktree 的 `.git` 是指向来源仓库元数据的文件。通用原生任务工具不能访问这些目录，macOS `/usr/bin/git` 启动器还需要读取开发工具选择信息；因此在受限 bash 中直接执行 Git 不能可靠完成本地提交。这属于缺少专用执行能力，不应通过放宽通用任务目录、网络或派生进程限制解决。

任务会话提供 `inspect_task_git` 和 `commit_task_code`。前者返回当前 HEAD、状态和未暂存／已暂存差异，后者只暂存并提交指定的相对文件路径，返回真实 SHA；其他暂存内容保留。只在用户要求或任务目标已包含提交时使用提交工具。工具仅注入后台任务会话，普通工作会话与全局会话不新增此能力。

服务端从持久化执行事实和项目主目录确定来源，按任务目录名验证 worktree 元数据、反向目录关联和任务分支；恢复沿用原目录时仍可使用。任务提供的 `.git` 指针禁止跟随符号链接且限量读取。每条 Git 命令前重新核对执行归属、边界和停止意图，拒绝改指针、改分支、越界、符号链接及整目录提交。

macOS 直接使用已选开发工具中的真实 Git，绕过 `/usr/bin/git` 的选择启动器。每条命令在 Seatbelt 中独立执行，环境白名单不继承服务端密钥；文件只读范围增加该任务所属的仓库元数据，写入仅增加该 worktree 元数据、公共对象目录、任务分支及其 reflog。其他分支、用户原工作区、内部数据和凭据目录不获得写权限，网络与 `process-fork` 继续默认拒绝。禁用系统／全局 Git 配置、系统 attributes、hooks、签名、外部 diff／textconv 和 clean／process 过滤器，也关闭自动维护。仓库 include 指向允许范围之外的配置时明确失败。

提交作者固定为 `Multivac <multivac@localhost>`，无需读取用户全局 Git 身份配置。通道不提供 push、fetch、checkout、reset、任意 Git 参数或外部程序执行；远端发布继续走已有的独立确认流程。符号链接、目录批量提交和自定义外部过滤器不属于这个能力集合。

Git 操作持有共享额度的原生工具租约，输出计入字节使用量。取消、输出超限、30 秒命令超时或应用关闭时终止确切的 ChildProcess，并等待 close 才结算；不能把发出 SIGKILL 或 error 事件等同于已经退出。管理工具沿用持久化调用账本，重放已完成的调用不重复提交。中断或结果未知时先查询 HEAD 和状态，不能直接重新提交。

`apps/server/tests/task-git.test.ts` 在临时仓库上实际验证查询、新增／修改／删除提交、主分支保护、无关暂存保留、hooks／签名／过滤器禁用、配置 include 越界、指针与分支篡改拒绝、环境隔离、输出限额以及取消后真实进程退出；另通过应用的任务工具链验证注入、额度记录、幂等重放和暂停门禁。应用链测试使用 fake adapter，Git 进程和文件操作是真实的；不能据此宣称真实模型已经完成用户任务。

## 受控托管候选后端

独立托管后端沿用 macOS Seatbelt 的禁止派生、目录与环境白名单，只执行任务目录内的 Node 脚本，不开放任意 shell 或 npm 工具链。可按启动声明放行一个 1024–65535 范围的 localhost TCP 监听端口，外连仍拒绝。端口只有在精确 PID 的 lsof 监听观测成功后才公开；创建进程不代表服务可用。

私有监护器位于沙箱外，通过专用管道接受停止，沙箱不能写日志存储或退出凭据。它在父服务管道断开或预算超限时请求停止，必要时升级 SIGKILL，等待 ChildProcess close 后原子保存带随机身份的退出凭据。因为沙箱禁止 fork，此证明覆盖整个允许的执行集合。缺少凭据时保留恢复核对，不按旧 PID 操作，不自动重新启动。

真实测试 `apps/server/tests/managed-processes.test.ts` 验证本地 HTTP 开发服务、长命令、外部文件读写拒绝、外连拒绝、密钥不继承、detached 后代创建拒绝、幂等启动、停止及预算收敛。生产入口仅注册在真实任务会话，普通工作会话与全局对话不能启动进程。启动前重新核对任务/Run/目录与租约；每任务最多四个、全局最多十六个未确认退出进程，单进程最多五分钟及 1 MiB 输出，并以启动时剩余执行预算收窄。依赖进程随本轮收敛；独立进程保留时阻止新 Run 复用目录。模型条件尚未验证，不以真实进程测试代替真实模型执行证据。
