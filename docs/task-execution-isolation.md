# 任务执行能力与停止核对

新建任务运行固定 `executionMode=workspace`，使用与工作会话相同的文件工具和 bash 托管后端。任务另行保留 Task/Run 身份、共享预算、依赖、暂停取消、恢复、成果版本与人工验收。执行能力对齐不授予 Agent 用户决定、扩大目录、MCP 调用许可或发布权限。

## 修改位置与文件授权

Git 项目默认从固定 HEAD 创建任务分支与独立 worktree，非 Git 项目采用有条目及字节预算的独立快照；不替换用户 dirty 工作树。主目录调整不迁移既有会话工作目录，恢复沿用已分配目录与分支。

两类会话的 read/edit/write 均使用 Pi 文件工具的执行前包装：逐次读取当前会话归属、项目主目录/附加目录和独立授权，按真实路径判断。卸载不撤销原 cwd 或独立授权；链接逃逸、目标变更、失效挂载不复用旧许可。范围外沿用已有 Inbox，批准后复核实际目标与原 Run；暂停取消后的迟到批准不能继续原调用。

文件工具授权不能拦截任意 shell 文件访问，cwd/worktree 不构成 shell 沙箱。书伴、笔记和项目终端不因本次改动获得其他工具。全局 Multivac 保留自身文件及 MCP 效果边界。

## bash、网络与环境

两类会话的 bash 接受可选 `cwd`：省略时使用原会话目录，显式值可选择原目录或当前已确认项目主目录、附加目录及合法子目录；相对路径基于原会话目录。调用时及异步准备后复核归属、挂载、真实路径与原 Run，实际目录进入进程记录及幂等指纹。文件独立授权不转为 bash 目录许可；全局只用原目录，旧隔离运行不支持指定 cwd。

两类会话共用 `BashProcessService`，可运行包管理器、构建、测试 worker、Chromium、开发服务器和本机 HTTP 测试；不再仅因任务身份禁止网络或派生进程。文件、bash、网页、MCP 的工具配置仍分别决定是否开放，未注入的工具拒绝调用。

前台/后台仅区别等待方式，所有 bash 均登记会话、执行、调用、进程组、退出码和日志。前台 timeout 限制运行时间，后台 timeout 只限制启动等待；任务的共享时间与输出额度仍适用于后台服务及子进程。启动前登记原 Run 租约，输出持续记账，后台返回 processId 不释放租约。时限由私有监护器收窄到启动时剩余额度，服务端持续复核 Run、停止状态与共享额度。

子进程只继承工作会话的运行环境白名单：PATH、HOME、TMPDIR、LANG、LC_ALL、SHELL、USER、LOGNAME、TERM；不自动继承其他服务端环境变量或模型密钥。这允许用户已有的包管理器和缓存，不代表 shell 无法按用户身份访问本机其他资源。依赖克隆是可选优化；未克隆时允许任务自主安装与修复依赖。

bash 启动的任务服务默认是本轮依赖，执行结束时收拢。`start_managed_process` 使用相同后端启动任务目录内 Node 脚本；`requiredWhileRunning=false` 明确声明独立长期生命周期，仍按启动时剩余时间/输出额度限制，输出计入原 Run，应用关闭时清理。它不因原任务结束自动归属新 Run，存在时保留目录占用。

## 停止证明与持久恢复

私有监护器在根进程启动后持续观察本次组及可靠识别的后代，记录 PID、进程组与启动身份。身份采样固定 C locale 和 UTC，避免中文日期格式改变解析。停止先保存业务意图，再请求 SIGTERM，宽限后 SIGKILL；发送前重新核对已观察进程的启动身份。根进程与已归属后代全部退出后，bash 监护器才原子保存含随机 token、根身份、累计输出和进程树退出事实的凭据。

不能以 shell 返回、Pi abort、发信号成功、管道关闭、owner 退出、租约超时或旧 PID 单独宣称停止。服务重启后只核对原 token、目录/Run/调用关联及退出凭据；已核实的 bash 凭据可结算原 pending 标记并补计未消费的输出，不重放命令。缺少证明、监护器异常或无法核对时保留 recovery 和资源占用，拒绝冲突启动。MCP 重启缺少本地关闭证明时同样保留原连接占用；本地停止不证明远端副作用已撤销。

这一机制不保证回收在采样之间主动脱组且已失去父关系、从未被观察到的进程，也不接管其他会话或系统服务。早期 `scripts/probe-task-stop.mjs` 的“仅发进程组信号仍有 detached 后代写入”反例继续成立，不能将本次改动解释为任意后代隔离。关闭浏览器不终止服务端任务；普通会话轮次完成和切换页面保留其后台服务，明确停止本轮/会话、归档和应用退出按所属范围清理。

## MCP、网页与 Git

stdio MCP 与 bash 共用环境和进程树托管方式，允许已配置的 npx/uvx 类启动器及子进程；HTTP 使用相同 HTTPS/回环 HTTP 地址准入。账号、服务、参数、目录/定义版本、效果分类与逐次真实用户许可仍固定并在实际发送前复核；任务连接和调用计入原 Run。取消后不新发请求，未知结果只读核对，不更换身份重放。网页工具保留显式配置、公网地址、服务商凭据及任务预算规则；共用 shell 的本机 HTTP 测试不改变网页工具地址范围。

`inspect_task_git`、`commit_task_code` 和 `read_git` 继续提供固定 worktree 的可核对入口。专用 Git 通道仍禁用 hooks、签名、外部过滤器和网络，提交指定文件并保留无关暂存；共用 shell 也能操作 Git 元数据，专用工具不是唯一写入路径。默认按逻辑单元核对后本地提交，用户明确提交策略优先；未知提交先对账 HEAD，不自动 push。外发仍走既有用户确认流程。

## 兼容与平台

缺少 executionMode 的历史 Run 按 `native-isolated` 解释，保留原身份及退出核对。已经启动或遗留的旧隔离进程不静默改成共用后端；旧排队运行也不因重启自动换模式。先核对停止，再由显式继续创建标记为 workspace 的新 Run，可沿用已分配的目录、分支与历史。界面及 get_task 均展示原执行方式。

旧 NativeTaskTools 和受限托管实现保留用于历史兼容；Skill 单文件脚本仍使用共同的 macOS 原生隔离，禁止网络、派生和自动安装，不随任务对齐放宽。专用受控 Git 和项目终端的实际平台限制保留。共用 bash/stdio 后端依赖 POSIX bash/ps，不支持 Windows；本次真实 OS 与浏览器证据为 macOS，不能据此宣称其他系统已验证。

## 验证入口

- `unified-task-execution-real-pi.test.ts`：真实 Pi + 本机脚本模型，两类会话在同一测试项目运行 npm 安装、失败测试、修改与复验、Chromium/HTTP；任务本地提交并固定成果为审核中，保留 dirty 原树。
- `unified-task-process-lifecycle.test.ts`：真实浏览器、HTTP 服务、脱组 worker，覆盖正常完成、暂停、取消、时间及输出额度耗尽、退出凭据和端口释放。
- `unified-mcp-transports.test.ts`：两类会话的真实 stdio 子进程/联网及回环 HTTP MCP，逐次许可、取消等待、拒绝迟到批准、重放不重复执行与后代停止。
- 文件边界、任务恢复/收尾、MCP 账号/版本/许可、普通会话 bash 和 Skill 使用原有相关回归，并为新执行方式补充用例。

模型响应脚本、真实 Pi、真实 OS、浏览器和外部真实模型是不同证据层。上述确定性链路不等于外部真实模型自主完成验收；实际执行结果与未验证项记录在 `artifacts/unified-task-execution/verification.md`，不默认运行全量测试。
