# 任务执行的隔离与停止验证缺口

任务数据接口已经可独立使用；执行、调度与面板仍未开放。本记录说明接入真实任务执行前发现的门禁缺口，不代表已经实现任务启动或暂停。

## 必须保持的边界

`docs/proj.md` 要求：工具文件访问、网络和子进程必须由经过验证的机制约束；无法确认旧执行停止时，不能释放冲突资源或启动冲突执行。用户授权不能绕过隔离失败。

当前 `pi-session-factory.ts` 注入本机 `read / bash / edit / write`。`pi-tool-boundary.ts` 对文件工具核对目录，对 bash 仅设置 cwd，并明确承认目录外影响未被拦截。这适用于现有工作会话，不能直接作为满足上述门禁的后台任务执行器。

## 实际探针

macOS Seatbelt 的受限 Node 子进程验证了目录外文件读写、符号链接访问与本地 TCP 连接可被拒绝；显式环境白名单可以避免继承服务端模型密钥。但这些结果不能证明整个任务已经停止。

依赖进程组的候选停止策略失败：子进程通过 `detached: true` 脱离进程组，启动器退出，向启动器进程组发送 SIGKILL 后，子进程仍在原任务目录写入。仅等待 shell 返回、Pi abort 返回或进程组消失不足以释放任务目录租约。

复现：

```sh
node scripts/probe-task-stop.mjs
```

在当前 macOS 主机得到：

```json
{"parentExited":true,"processGroupStopped":true,"detachedChildWroteAfterStop":true,"safeToReleaseLease":false}
```

退出码 1 表示停止安全门禁未通过。该探针只执行受控代码，创建并清理自己的临时目录，按返回的精确 PID 清理子进程；不调用模型、不使用用户项目、不验证 Windows。文件读取规则刻意简化以复现生命周期问题，不能用作生产沙箱配置。

真实 Pi 最小 smoke 另行运行，因未设置 `MULTIVAC_PROVIDER` 在准入校验处失败；`MULTIVAC_MODEL` 同样未配置。此结果不是模型执行失败，也不是真实任务执行证据。不得从普通测试中的 fake adapter 通过推断真实模型通过。

## 继续实现需要明确的运行前提

- 保留原生任务执行：需要跨平台可验证的进程生命周期隔离、文件/网络约束、凭据隔离与停止核对后端；不能把 worktree 或 cwd 当作替代。
- 采用容器或虚拟化任务执行：可以用隔离实例的终止与状态核对约束整个子进程树，但会新增产品部署前提，也会改变工具环境、构建工具链和项目目录挂载规则。当前开发主机存在可用的本地 Docker/OrbStack，尚未将其作为产品依赖或注入任务执行器。

在运行前提明确且验证通过之前，保持任务未执行，保留持久记录，不发布不可用的执行入口，不跨过真实执行这一项的验证门禁。
