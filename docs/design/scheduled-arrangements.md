# 独立定时安排

Schedule 保存版本化的动作和时间规则，Occurrence 保存一次计划或手动触发的快照。两者不属于任务树，不创建 Task/TaskRun，不进入任务验收。提醒和 Agent 共用此模型。

## 时间与命令

- 支持单次、每日和每周多个星期几。使用明确的 IANA 时区；不支持任意 cron。
- 单次保存绝对时刻、当地日历时间和时区，并核对一致性。重复日历时间必须提供明确偏移，不能从文字猜测。
- 周期按当地日历计算。DST 重复取较早偏移；不存在的时刻保留原日历标签，使用变化后的候选时刻作为记录水位，只记录跳过，不执行动作。
- 预览与调度复用 contracts/schedule-time。计算仅依赖运行平台的 IANA 时区数据库；系统时区库更新可能改变未来预览。
- 命令绑定来源和 commandId，重试返回原回执，参数变化报冲突。修改核对 revision。计划身份使用安排 ID 和绝对时刻，跨版本不重复；手动身份使用来源和 commandId，不移动原计划。
- 删除只写墓碑，保留触发快照、会话和通知。暂停阻止尚未开始的后续触发，不停止在途；重新启用从未来继续，暂停期间不补跑。停止只作用于本次。

## 执行边界

服务关闭或系统休眠时无法准时执行；不提供 OS 唤醒或多设备调度。周期与 Agent 默认跳过错过时间，可选仅补最近一次；旧单次提醒继续按原承诺补发。同安排在执行、人工等待、停止和结果核对期间均不重叠。

每轮 Agent 使用独立会话，按当前 Agent、模型、项目目录和工具配置核对并保存执行快照。目录不是沙箱，也不提供跨安排文件互斥。指令不扩大权限；人工授权使用原有 Inbox 入口。结果仅进入 Inbox，不自动发送微信。

副作用前先保存触发身份；服务恢复时，未开始的触发可重新领取，可能已发生副作用的执行进入待核对，不自动重发。租约到期不能证明旧执行已停止。

## 原型参考

参考 prototypes-scheduled-arrangements@727b458 的 prototypes/schedule-panel.jsx：状态筛选、类型与搜索、左侧列表与右侧详情、新建编辑、近期预览、当前轮次及历史。正式实现使用持久服务、真实模型和现有确认组件，不能沿用原型的示例数据或模拟计时器。正式页面位于“管理 → 工作 → 定时安排”，共享页面 ID 与快捷跳转注册表。与原型的适配差异：

- 列表按服务端分页，不使用原型内存数据；默认展示启用安排，另有暂停、已结束、已删除筛选。名称搜索和类型筛选参与服务端查询。
- 左侧列表、右侧详情保留；正文可用宽度不足 640px 时上下排列，列表限高；手机沿用正式管理区“请在桌面使用”门禁，不承诺手机完整管理。正式页面使用已有色板、按钮和确认卡，不复制原型的应用外壳。
- 每轮额度展示毫秒、字节和工具调用数，默认值读取当前偏好并写入安排。原型的演示预算替换为有限真实额度。
- 单次 DST 重复时刻列出实际 UTC 候选，必须明确选择；周期固定使用较早偏移。预览中的缺失时刻显示“将跳过并记录”。
- 每项危险或会执行的控制先展示原有确认卡；删除在活动轮次结束前不可用，停止与暂停分开。
- 历史使用服务端分页，并提供原会话、Inbox 和本轮固定快照。待恢复核对保留占用，没有盲目重跑或自动解除入口；等待人工跳转现有 Inbox。
- 双窗口与重连依靠 schedules.changed/workbench.connected 重读；请求序列防止迟到覆盖。写操作先在本标签页保存原 commandId，响应未知时先核对回执，可显式重试无回执的原命令。

## 接口与运维

本机管理 API 位于 /api/schedules，创建、编辑和控制分别使用稳定 commandId，修改带 revision。详情的历史支持 offset/limit；查询不改变执行状态。管理接口沿用本机 Host/Origin 门禁和远程默认拒绝规则。

统一调度每秒扫描，迟到超过 60 秒按错过策略处理；长期离线用区间记录压缩，避免无限补扫。暂停期间不补跑。系统时钟回退由唯一计划身份去重。

停止事实未知或服务重启遇到在途 Agent 时保留 reconcile，占用不会自动解除。用户可检查原会话、进程和副作用；本版不提供将未知结果改写成成功的恢复按钮。服务关闭不会保证外部 MCP 操作已停止。公开结果只声明已观测事实。

旧提醒迁移保留 ID/revision、原命令回执及 notification:<reminderId>:<revision>。已 claimed 的本地通知通过事务和唯一 ID 核对，不并行启动旧提醒调度器。旧单次改为周期后保留原回执与旧通知，旧单次入口标记为已取消；新周期每轮按 Occurrence 生成通知，旧工具不能覆盖新周期。知道了只处理通知，不暂停安排。Agent 通知标记为 agent，现有微信渠道明确排除该来源。

## 验证边界

自动化使用 Fake 模型提供确定的工具调用；SQLite、HTTP、独立会话、bash 文件输出、真实进程启动/停止、Inbox 等待及预算限制使用正式实现。真实模型的选工具和自然语言解释、远端 MCP 取消证明与真实微信账号收件仍需在具备配置的环境独立验证。不能把 Fake 通过当作真实模型或外部送达验收。
