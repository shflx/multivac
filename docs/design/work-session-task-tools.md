# 工作会话的任务查询与更新

工作会话可使用 `list_tasks`、`get_task`、`list_task_groups`、`update_task`、`complete_task`，读取正式任务的目标、范围、验收要求、依赖、状态和最新 revision，再按用户安排推进工作。查询可跨项目定位任务，但查询结果不授予目标项目的目录访问或执行权限，也不自动将查到的任务变为当前工作。

属性更新复用已有任务服务，保留版本冲突、关系、执行中边界、预算和终态校验。更新成功不表示任务启动、完成或通过验收。普通工作会话不因此获得创建、删除、控制任务或代用户回应人工请求的工具。任务执行会话额外保留绑定当前运行的澄清和成果登记工具。

工具说明由实际注入的集合生成，不改变工作会话身份；开始处理正式任务时先查事实，版本冲突后重新核对。创建和恢复会话都注入对应集合。有副作用的调用继续使用会话 ID 与 toolCallId 派生的幂等命令，重放不重复更新；变更沿用公共事件同步到任务界面。

服务更新后，新建及从持久化记录恢复的工作会话获得这些工具；已在旧服务进程内初始化的 Pi 会话不热替换工具，需要重启服务后恢复。

工作会话手动做完无后台运行记录的任务后，用 `complete_task` 提交完成说明（具体结果、核对情况、交付位置），来源会话由服务端调用身份提供。无需人工验收时状态转为 done；需要验收时转为 review，创建绑定报告 ID 的请求，用户接受后转为 done，要求修改时保持暂停并保存意见，不自动启动后台任务。再次提交保留旧说明及请求历史。依赖未完成、存在其他待处理请求、任务已终结或已有后台 Run 时拒绝；后台 Run 继续使用原成果核对流程。完成说明在详情和查询中可读，并能返回来源会话；它是会话提交的工作记录，不冒充服务端独立验证的成果。

依赖统一按真实状态判断：审核中（review）和已完成（done）均满足依赖；其他状态不满足。审核退回修改后，未启动的后续重新等待，已启动的后续不自动停止或回滚；之后完成或验收仍核对当时的前置条件。子任务完成统计仍只计算 done，不将审核中冒充已完成。

成果审核集中在任务面板和任务详情中处理，对话不显示审核请求卡片及其已回应、已失效回执。交付一组任务后，对话用一段自然语言汇总结果与核对情况，必要时附任务链接，并说明可在任务面板查看和审核；不逐项催促或自动打开面板。审核中不等于已验收；仅登记后台成果提交意图时不能提前宣称交付完成。澄清、恢复及目录授权仍保留原有对话入口。

“我来处理”是同一任务体系中的系统标记 `humanOnly`，默认 false，旧记录缺省也按 Agent 处理。创建、详情编辑和列表／看板提供标记与处理方式筛选，筛选在服务端分页前完成。勾选后隐藏 Agent 启动入口，改为“标记完成”；完成不创建 Run，也不生成成果验收请求，但仍核对版本、前置依赖及待处理请求。已进入执行流程、有后台运行记录或有待处理请求时不可切换标记；终态只读。

Agent 不按开会、电话等标题猜测执行责任。工具设置或移除标记时要求 `userConfirmation` 引用用户主动表达或确认；已有明确表达无需重复询问。用户明确说已做完时可通过 `confirm_human_task` 代为记录，不能以时间到达或模型判断推断完成。该字段是调用方提交的用户表达依据，不是服务端对自然语言授权的独立判定；调度禁止和完成类型限制由服务端强制执行。创建提议在确认卡上显示处理方式，由用户确认后才落库。

本版不提供定时提醒按钮或自动提醒承诺；单次提醒、稍后提醒及系统通知需后续接入真正的提醒服务。
