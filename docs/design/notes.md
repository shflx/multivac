# 独立笔记应用

本文描述当前实现与本地核验方法。产品入口为“管理 → 应用 → 笔记”，全局 Multivac 对话也可查询和读写独立笔记。笔记应用参考固定原型 `prototypes@d52053a85bba2bc385e79bfb624978afda801436`，已接入当前主线的统计与智能体功能。

实现包含数据、编辑、讨论、建议及全局对话操作路径。自动验证使用真实业务服务、SQLite 和 Pi SDK，模型输出由回环脚本或 E2E 夹具提供；这些验证不代表外部模型访问和回答质量验收。

## 使用流程

1. 从笔记库新建笔记，填写标题与 Markdown 正文，点击保存。更新时间和正文版本来自服务端。
2. 打开右侧梳理助手，直接提问，或使用整理结构、润色、梳理关联、生成修改建议。发送前保存编辑内容，服务端冻结已保存版本；发送过程中再次编辑时，保留新输入并要求再次保存后发送。
3. 在 Markdown 原文中选择文字，可引用给助手或深入一层。深入讨论保存父讨论身份、固定主题及父层实际模型快照。返回上一层或下拉选择已有讨论不会删除子层。
4. 建议回复包含约定 JSON 时，点击“查看修改建议”。服务端核对真实历史及来源快照，形成理由、修改前后内容和状态卡片。这个步骤不会修改正文。
5. 拒绝保留正文；接受只替换经服务端核对的唯一连续原文。刷新后恢复正文及决定。正文版本发生变化时，其他未处理建议全部失效，包括接受一条建议导致的变化；需基于最新正文重新生成。

梳理关联仅讨论本笔记已有内容。页面不包含交给 Multivac、收进笔记、知识库、跨页面引用、跨应用检索或内容收集入口。

## 全局 Multivac 操作独立笔记

用户可在全局对话中要求“查找会议笔记”“读取这篇笔记”“新建笔记并保存以下内容”或“将已核对的笔记标题改为会议纪要”。写入按明确要求直接执行；仅讨论建议时不修改正文，同名或指代不明确时先澄清。

| 工具 | 行为 |
| --- | --- |
| `list_notes` | 按标题关键字查找并分页返回摘要、稳定 id 和最新 revision；不返回正文 |
| `read_note` | 按 id 读取正文，每页最多 12000 个 UTF-16 字符；继续分页带返回的 revision 与 nextOffset，固定同一不可变版本 |
| `create_note` | 用稳定 requestId 创建笔记，服务端派生笔记身份，原请求重试不重复创建 |
| `update_note` | 指定 id、revision 和 title/body 中需修改的字段；事务中保留其他字段，版本冲突不覆盖 |
| `get_note_operation` | 只读查询原 requestId 的已提交保存回执，并区分当次保存版本与当前版本 |

requestId 标识一次用户写入，独立于模型的 toolCallId。新建、正文与版本快照、请求回执在同一事务提交；跨工具调用或重启重试沿用原 requestId 和参数，不换身份盲目重写。同一请求参数变化被拒绝。`saved` 只代表当次保存确已提交；`not-recorded` 表示未找到已提交回执，不能说已保存。已保存但回传故障时先查询回执，再读取当前笔记。

写入复用 `NotesService`，通过 `notes.changed` 同步到笔记库与编辑器。无本机修改时采用服务端新版本；有草稿时保留输入并展示冲突，刷新恢复草稿也核对服务器版本。操作回执提供笔记应用入口，保存本身不切换页面。

仅全局 Multivac 注入这些工具；工作会话、任务会话、书伴与笔记梳理助手不注入。正文及标题是用户资料，不能提升为系统指令、用户接受或权限授权。不操作书内阅读笔记，不跨应用收集内容或加入知识库。

## 持久化与模块归属

| 内容 | 权威来源 | 实现 |
| --- | --- | --- |
| 笔记身份、标题、正文、版本和时间 | SQLite 独立 `app_note`、不可变 `app_note_version` | `notes.ts` 契约、`NotesService`、`SqliteNotesRepository` |
| 幂等命令及原请求回执 | `app_note_command` | 新建、保存、快照、深入、导入建议和决定共享命令账本 |
| 本机未保存正文及未知保存请求 | 独立 localStorage 草稿键、标签页 sessionStorage 指针 | `note-draft.ts`、`NoteEditor` |
| 根讨论、父子关系和固定主题 | `app_note_discussion`、会话 registry 的 note host | `NoteAssistantService`、`SqliteNoteAssistantRepository` |
| 本轮版本及选区 | `app_note_context`，外键指向不可变正文版本 | 发送仅传 snapshotId；模型正文由助手服务读取 |
| 对话正文及消息来源 | 真实 Pi session，custom context 落盘 | Pi adapter、历史投影、共享会话控制器 |
| 对话草稿、未知发送与重试 | 既有会话页面状态、命令及控制器 | `useAssistantSession`；每讨论独立身份 |
| 修改建议及决定 | `app_note_suggestion`、来源去重表 | `NoteSuggestionsService`、建议 repository |

独立笔记表与读书页阅读笔记表完全分离，不自动迁移。SQLite 迁移追加在现有迁移末尾。笔记讨论通过稳定 host 标识，不进入工作会话列表，不允许归入项目或浏览会话目录。

写正文、版本、建议决定及命令回执采用短 `BEGIN IMMEDIATE` 事务，不在事务内等待模型。普通编辑和接受建议都会使旧版本待处理建议失效。工作台变更事件用于通知重读，连接恢复及窗口重新聚焦补读事实。

## API

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/notes` | 笔记摘要列表 |
| `POST /api/notes` | 带稳定笔记 ID、commandId 创建 |
| `GET /api/notes/:id` | 读取正文及版本 |
| `PUT /api/notes/:id` | 使用 expectedRevision 保存；旧版本报冲突 |
| `POST /api/notes/:id/companion` | 幂等取得根讨论 |
| `GET /api/notes/:id/discussions` | 恢复讨论列表 |
| `POST /api/notes/:id/discussions` | 从父层稳定消息或选区快照深入 |
| `POST /api/notes/:id/contexts` | 冻结正文版本、逐字核对选区 |
| `GET /api/notes/:id/suggestions` | 读取持久化建议与决定 |
| `POST /api/notes/:id/suggestions` | 从服务端稳定 Pi 助手历史导入结构化建议 |
| `POST /api/notes/:id/suggestions/:suggestionId` | 带版本及 commandId 接受或拒绝 |

讨论发送、停止、选模、分页历史、草稿及命令核对沿用既有 `/api/sessions/:sessionId/...` 接口与全局事件流。新增路由沿用本机 Host/Origin 与远程访问范围门禁。

## 冲突与来源保护

同命令不同参数拒绝；同命令重放返回原回执。浏览器把未知保存的原 commandId 和 payload 保存在草稿中，重试先核对原请求，不把新输入替换进旧命令。旧回执只推进基线，保留之后编辑的正文。

多窗口更新必须匹配服务端版本。有本机草稿时，远端新版本只进入冲突对照区，不替换输入。用户核对内容、明确选择最新基线后才能继续保存。本机存储失败显示错误，保留内存输入并提醒保持页面打开。每次挂载用独立持久键，避免复制标签页后的草稿互相覆盖。

快照绑定笔记、讨论和正文 revision。选区使用 UTF-16 偏移与确切原文，端点不能拆开代理对；带选区发送时正文版本变化要求重新选择。模型上下文包含该版本全文、可选选区和独立固定主题，历史正文不能代替本轮版本。Pi 用户及回复历史投影保留各轮 noteContext。

模型输出仅允许建议理由、before 和 after，不能指定目标笔记、版本、位置或决定。建议导入从服务端可读且不在运行中的 Pi 历史核对稳定身份，原文不存在或不唯一时整批拒绝。接受时再次核对正文版本、唯一原文和确切位置，重复接受不再次写正文，相反决定被拒绝。有未保存草稿、未知保存或冲突时，界面禁止接受。

笔记助手复用真实 Pi 及选模、流式与取消链路。运行配置禁用文件、命令工具，且不注入内部工作工具；服务器拒绝笔记发送中的跨应用上下文、引用、图片和运行中追加。生产实现没有模拟回复分支。测试目录的受控模型及 Fake E2E 仅用于验证链路。

## 边界及当前限制

正文上限 100000 个 UTF-16 字符，助手全文上下文上限 48000，选区与固定主题上限 16000。超出助手上限的笔记仍可编辑保存，讨论要求拆分；不会静默截断。笔记库最多 1000 篇，每篇最多 100 个讨论、2000 条建议，讨论层级最多 16 层。

每条建议基于完整正文版本，接受一条后剩余待处理建议失效是保守的版本保护策略。没有自动重定位、合并应用或撤销已接受建议入口。编辑器直接编辑 Markdown 原文，没有额外预览模式。视觉布局目前以桌面三栏为重点；未取得窄屏可用性或截图核对证据。

真实模型可能不按 JSON 协议输出；服务端会拒绝格式或定位不合格的输出，要求重新生成。全局对话按工具说明及提示词判断用户意图，服务端校验工具范围、稳定身份、版本及幂等请求；不把脚本模型的工具选择当作真实模型理解意图的证据。

## 本地自动验证

在正常的仓库工作目录，安装依赖并使用 Node >=22.19.0；浏览器部分需要 Playwright Chromium。不要在当前禁止派生进程的任务环境运行该脚本。

```bash
node scripts/verify-notes.mjs
node scripts/verify-notes.mjs --browser
```

首条执行仓库类型检查、新增迁移 SQL 和模块引用检查、针对性笔记服务及受影响会话/阅读回归、Web 草稿与导航用例。第二条额外执行 `tests/e2e/notes.spec.ts` 与 `tests/e2e/multivac-notes.spec.ts`；浏览器用例使用既有临时 E2E 数据和受控模型夹具。脚本按实际退出码写入 `artifacts/notes-local-validation.json`，失败后的检查保留 not-run，不能把未运行项当成通过。

SQL 检查另写 `artifacts/notes-static-validation.json`，只代表新增迁移与显式约束检查，不代表完整升级或运行闭环。真实 Pi 历史用例采用回环脚本模型，检查 SDK、快照写盘/恢复与禁用工具，不验证外部模型访问或建议质量。

## 真实模型与人工核验

使用正常本地服务和已配置可用模型，确保没有启用 `MULTIVAC_FAKE_ASSISTANT`。创建一篇有两处唯一原文的笔记，完成编辑、保存、选区引用提问、生成建议、先拒绝再接受、刷新恢复。保留本轮模型、正文版本、Pi 消息身份与建议决定截图；不要在报告中保存密钥或认证文件。

另外核对：流式期间停止及终结反馈；输入下一条草稿后原发送失败/未知结果的恢复；深入、子层独立选模、返回与服务重启后的各层历史；两窗口并发编辑和显式冲突处理；人工编辑后旧建议失效；重复接受无重复替换；重复原文建议无法导入；服务重启后正文、建议与历史恢复；笔记与阅读笔记独立且笔记助手没有文件/工作工具。

原型范围对照见 `docs/notes-prototype-comparison.md`。自动验证脚本输出实际状态；全局笔记工具回归另覆盖同名查询、固定版本分页、部分更新、并发与重启重试、回传故障对账，以及对话写入后的多窗口草稿保护。真实模型的自然语言理解、写入意图判断与回答质量仍须人工核验。
