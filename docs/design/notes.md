# 独立笔记应用

入口为“管理 → 应用 → 笔记”。笔记助手只用于围绕当前笔记讨论，每篇笔记对应一个固定的主对话，不再提供分层讨论、快捷提问或结构化修改建议的采纳流程。

## 使用流程

1. 从笔记库新建笔记，填写标题与 Markdown 正文，点击保存。
2. 打开梳理助手，直接输入问题。每次发送前保存当前编辑内容，并将当时的笔记正文作为本轮上下文；历史正文不能代替当前内容。
3. 需要讨论某一段时，在 Markdown 原文中选择文字，点击浮条中的“引用”，再输入问题。引用可以移除，正文变化后需重新选取。
4. 对话支持流式回答、停止、模型选择、读取较早消息及刷新恢复。助手以普通文字回答，改写内容也只作为聊天文本，由用户自行编辑笔记。
5. 左侧笔记列表仅在选中条目的标题区域右侧显示删除入口，操作需明确确认；正文、全部历史版本和本机未保存修改一起清理，无法通过版本历史恢复。

页面保留聊天记录和输入框，不展示讨论层级、版本徽标、修改建议卡片、接受或拒绝操作。助手不修改笔记、不安排任务，也不跨应用搜索或收集内容。

## 编辑与布局

笔记库使用扁平列表，搜索仅匹配标题，不切走当前编辑对象或丢弃草稿。正文是页面视觉中心，采用自然撑开的 Markdown 输入框，与标题在文档区统一滚动。

标题可直接点击并随内容换行。Enter 转到正文，Esc 还原本次仍处于原基线的标题输入，保留正文及原保存请求。Ctrl/⌘+S 与保存按钮共用保存流程。保存失败与版本冲突提示留在滚动区外。

编辑模式直接编辑 Markdown 原文；阅读模式渲染当前草稿，切换不隐式保存。两种模式共享同一份原文和版本保护，分别保留滚动位置，返回编辑时保留正文光标。

拖选结束后，在选区附近显示仅含“引用”的小浮条，不占正文空间。选区滚出可视区时隐藏，取消选择、Esc 或点击其他位置时收起。Tab 进入引用按钮，Esc 返回正文并保留原选区。专注写作中引用会退出专注并展开助手，准备失败也会在助手中显示原因。

梳理助手首次默认收起，保留用户选择的展开状态。首次展开或选取引用时才准备主对话；首次展开后保留会话控制器。收起助手、切换笔记或进入专注写作时暂停隐藏助手的模型轮询，重新显示时立即核对模型状态；草稿、运行与事件处理继续保留。专注写作临时隐藏笔记库和助手，不卸载组件，退出时恢复输入。宽内容区并排显示笔记库、正文与助手；内容区收窄后，助手排在正文下方，笔记库进一步收为顶部横向列表。布局按实际容器宽度响应，包括 Multivac 侧栏挤压页面的情况；不超过 760px 的窗口沿用外壳“管理请在桌面使用”的规则。

## 版本历史

工具栏的时钟入口打开版本历史。每次标题或正文实际变化并保存后，保留不可变版本；无改动保存不额外增加版本。已有快照直接可见，不扫描或回填历史。

版本按新到旧排列，摘要包含版本号、保存时间与当时的标题，按版本号游标分页，每次默认 20 条、最多 50 条。预览只读，选取历史不会替换当前编辑内容；新保存不会打乱较早版本分页。

“恢复此版本”将旧标题与完整正文作为一次普通保存，生成新版本，保留原来的最新版本和所有旧快照。内容与当前一致时不提供重复恢复。未保存草稿、待核对保存、并发冲突或保存进行中仍可查看历史，处理完成后再恢复。

恢复复用编辑器原有命令与草稿账本。响应丢失时保留原请求，核对重试不重复创建版本，也不丢弃后续输入。同步事件先到达时仍允许核对原请求；若之后另有更新，旧回执不会清除更新后的冲突。历史窗口支持 Esc 关闭及返回入口焦点。

## 讨论与保存保护

每篇笔记通过 `POST /api/notes/:id/companion` 幂等取得稳定主对话。页面不查询讨论列表或建议，不创建子讨论；旧的子层选择不再决定当前会话。历史子讨论和建议记录保留在数据库中，不自动合并、迁移或删除。

发送前通过 `POST /api/notes/:id/contexts` 冻结已保存正文版本和可选引用片段，发送只传 snapshotId。服务端核对笔记、会话及正文 revision，并从不可变版本读取上下文。选区使用 UTF-16 偏移与确切原文，端点不能拆开代理对。历史用户消息与回复保留各轮 noteContext。

助手复用真实 Pi 及共享会话控制器的选模、流式、停止、分页历史、草稿与发送核对机制。运行配置禁用文件和命令工具，不注入内部工作工具；服务器拒绝跨应用上下文、图片和运行中追加。正文、标题及选区是资料，不授予指令或权限。

未知发送沿用原命令和正文快照核对或重试，失败提问可恢复为草稿。发送准备期间不丢弃后续编辑。保存失败时保留原 commandId 和 payload，重试不把新输入替换进旧命令，旧回执只推进基线。

多窗口更新必须匹配服务端版本。有本机草稿时，远端新版本只进入冲突对照区，不替换输入；用户明确选择最新基线后才能继续保存。刷新恢复草稿也核对服务器版本。本机存储失败显示错误并保留内存输入。

## 删除笔记

删除按当前正文 revision 校验，并使用稳定 commandId。保存进行中、原保存结果待核对或版本冲突时暂停删除；助手正在回答时服务端拒绝删除，须先停止或等待结束。确认期间产生新版本也会拒绝旧删除请求，重新核对后再操作。

删除在同一 SQLite 事务中清理全部版本、上下文快照、旧建议及来源索引，并清除旧命令回执携带的正文。只保留无正文的笔记身份标记和命令指纹，禁止同一身份重建及旧写入重放。关联讨论归档并释放运行时，保留笔记宿主归属，不能恢复为工作会话；既有 Pi 聊天文件不作为笔记版本恢复来源。

各窗口通过列表重读关闭已删除笔记，清理对应本机草稿；迟到的读取与保存回执不能重新写回已删除对象。删除响应丢失时保留原命令并暂停编辑，重试核对原请求；刷新后也可据完整列表确认对象已经删除。

## 数据与 API

独立笔记与读书页阅读笔记完全分离，不自动迁移。笔记身份、标题、正文及不可变版本存于 `app_note` 和 `app_note_version`；幂等命令回执存于 `app_note_command`。主对话通过 `app_note_discussion` 及会话 registry 的 note host 关联，版本快照存于 `app_note_context`，聊天正文由真实 Pi session 持久化。

旧的讨论分层和建议服务及其数据保护仍保留，当前页面不调用这些操作，不为简化界面清理已有数据。

笔记列表在 SQLite 内移除正文后一次返回摘要，不逐篇读取完整笔记；容量限制使用计数查询。版本列表和讨论身份查询只需摘要时不读取完整正文。页面合并在途列表请求，读取期间发生的变更会安排后续核对；已打开的编辑器按摘要中的新版本读取正文，切换笔记不重复读取未变化的正文。若读取期间又有新版本，继续核对最新已知版本，保留本机输入和冲突提示。

| 方法与路径 | 当前页面用途 |
| --- | --- |
| `GET /api/notes` | 笔记摘要列表 |
| `POST /api/notes` | 带稳定笔记 ID、commandId 创建 |
| `GET /api/notes/:id` | 读取正文及版本 |
| `PUT /api/notes/:id` | 使用 expectedRevision 保存，旧版本报冲突 |
| `DELETE /api/notes/:id` | 带 commandId / expectedRevision 删除，全部历史版本同事务清理 |
| `GET /api/notes/:id/versions` | 分页版本摘要，支持 before / limit，返回最新版本号及下一页游标 |
| `GET /api/notes/:id/versions/:revision` | 只读获取指定版本的标题与完整正文 |
| `POST /api/notes/:id/companion` | 幂等取得主对话 |
| `POST /api/notes/:id/contexts` | 冻结正文版本及引用片段 |

讨论发送、停止、选模、历史与草稿沿用 `/api/sessions/:sessionId/...` 及全局事件流。路由沿用本机 Host/Origin 与远程访问范围门禁。笔记会话不进入工作会话列表，不允许归入项目或浏览会话目录。

正文上限 100000 个 UTF-16 字符，助手全文上下文上限 48000，引用片段上限 16000。超出助手上限的笔记仍可编辑保存；讨论要求拆分，不静默截断。

## 全局 Multivac 操作独立笔记

全局对话可查询、读取、新建和更新独立笔记。仅按用户明确写入要求或已接受的修改内容写入；只讨论建议时不修改正文，同名或指代不明确时先澄清。

| 工具 | 行为 |
| --- | --- |
| `list_notes` | 按标题关键字分页返回摘要、稳定 id 和最新 revision，不返回正文 |
| `read_note` | 按 id 读取，每页最多 12000 个 UTF-16 字符，后续分页固定同一 revision |
| `create_note` | 使用稳定 requestId 新建，原请求重试不重复创建 |
| `update_note` | 指定 id、revision 和要修改的字段，保留其他字段，版本冲突不覆盖 |
| `get_note_operation` | 只读查询原请求回执，区分当次保存版本与当前版本 |

requestId 独立于模型 toolCallId。写入、不可变版本和原请求回执在同一事务提交，跨调用或重启重试沿用原身份和参数。参数变化被拒绝；未知结果先查询回执，再读取当前笔记，不换身份盲目重写。`saved` 只代表当次保存确已提交，`not-recorded` 表示未找到已提交回执。

写入复用 `NotesService`，通过 `notes.changed` 同步编辑器。无本机修改时采用服务端新版本，有草稿时保留输入并展示冲突。保存本身不自动切换页面。

只有全局 Multivac 注入笔记操作工具；工作会话、任务会话、书伴与笔记助手不注入。标题和正文不能提升为指令、用户接受或权限。工具不操作书内阅读笔记，不跨应用收集内容或加入知识库。

## 验证

使用 Node >=22.19.0 及仓库依赖，浏览器验证还需 Playwright Chromium：

```bash
node scripts/verify-notes.mjs
node scripts/verify-notes.mjs --browser
```

脚本执行类型、迁移静态检查、针对性服务和草稿回归；浏览器部分执行 `tests/e2e/notes.spec.ts` 与 `tests/e2e/multivac-notes.spec.ts`，覆盖普通讨论、最新正文、选区引用、主对话恢复、旧数据保留、草稿保护、版本查看与恢复、分页及迟到响应、布局及全局笔记工具，也覆盖助手按需启动、隐藏轮询暂停和读取期间的连续更新。旧持久层的分层和建议测试继续验证已有数据服务，不代表页面保留相应入口。

真实 Pi 历史用例使用回环脚本模型，检查快照写盘、恢复和禁用工具；Fake E2E 用于验证交互。它们不证明外部模型访问、自然语言理解或回答质量。人工核验应使用已配置模型，检查普通提问、笔记更新后继续讨论、引用、流式停止、失败恢复及两窗口冲突；不要在报告中保存密钥。
