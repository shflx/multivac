# 工作区文件操作

文件树、搜索结果和当前文件标题使用相同的右键菜单与可见更多按钮。菜单操作绑定该入口的会话、原工作目录、路径与目标类型，不使用另一个选中项或并排栏焦点。Shift+F10 打开菜单，方向键移动，Esc 关闭并返回更多按钮。最近查看与根目录也提供对应菜单。

复制绝对路径和名称时，服务端重新核对原根目录、可浏览范围、符号链接及目标类型，返回真实路径和名称。前端原样写入剪贴板，只有写入成功后才提示成功。文件名含扩展名，目录复制目录名。目标失效、目录变更或剪贴板拒绝均反馈错误。

“引用到当前会话”只用于文件。点击时立即将该菜单的固定来源写入所属工作会话的单个引用草稿，保留正文和图片，不自动读取全文或发送，也不等待异步预检来覆盖后续引用。来源引用使用 `sourceKind: file`、`quoteKind: source`、空 `text` 和固定 `sourceFile.root/path`；它不能携带行号、章节或伪造正文。旧文件选区缺省仍为选区，必须有非空文本，保持原快照和大小限制。

来源引用不依赖文本预览，因此二进制及超过预览上限的普通文件也可引用。发送前重新校验文件类型、原根目录和路径；跨会话的文件来源发送被拒绝。模型收到明确来源位置和原权限说明，读取仍受原工具及目录边界限制。来源失效时保留草稿。来源类型和身份随原命令进入幂等指纹，未知结果沿用原命令及快照，已发送历史保存原来源。

“在文件管理器中显示”使用本机 POST 入口。前端要求可信点击事件和当前用户激活；服务端要求实际本机访问身份、回环对端、匹配 Host 的本机 Origin 和同源浏览器 Fetch Metadata，拒绝仅在正文或请求参数中声称用户点击的请求。远程路由白名单仍拒绝整个文件接口。其他平台明确提示不支持。

macOS 文件通过固定 `/usr/bin/open` 和 `-R`、绝对路径参数请求 Finder 选中；目录通过固定 Finder 应用打开，包括 `.app` 等目录也不把目标当应用启动。参数不经 shell 拼接，路径必须是已验证的绝对路径。启动过程限制时间和输出，等待退出后才返回命令结果；结果未知时不自动重试，回执不保证桌面已经显示。原根、目标类型和文件身份在启动前复核，未放宽符号链接或内部目录限制。路径核对和操作系统启动之间仍存在外部文件变更的竞态，不能视为原子文件系统操作。

本机来源和 Fetch Metadata 属于现有浏览器 HTTP 边界，不能证明任意本机程序具有真实用户手势。具备本机免登录 API 访问能力的非隔离进程仍可仿造 HTTP 请求头；这与项目既有本机 API 缺口一致，不能把该检查描述为本机进程隔离。模型文字和内部工具没有定位接口，任务隔离继续禁止网络与派生进程。

针对性验证包括目标服务、来源契约、Pi 历史、发送幂等、草稿控制器及定位路由/启动器；浏览器用例位于 `tests/e2e/file-actions.spec.ts`、`tests/e2e/file-source-quote.spec.ts` 和 `tests/e2e/file-reveal.spec.ts`。系统定位浏览器回归使用模拟响应，不启动真实 Finder。运行结果与本机实测限制由交付成果记录。
